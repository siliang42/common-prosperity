# 参与贡献

## 先搜索，再提问

提问前先翻一遍 Discussions 和已关闭的 issue。很多问题在「复盘」分类里已经有结论，包括那些最后证明走不通的路。

## 讨论放在 Discussions

- **问答**：怎么用、为什么这样设计
- **想法**：想加什么功能、想验证什么假设
- **复盘**：策略上线或放弃之后的回顾，失败案例同样欢迎
- **工具**：外部工具、数据源、库的取舍

Issue 只用来记录两类东西：**能复现的缺陷**、**明确的需求**。

## 报告缺陷

请带上：

1. 复现步骤，从打开哪个页面开始
2. 期望结果与实际结果
3. 相关的日志片段（**先去掉密钥**）
4. 运行环境：系统、Python 版本、浏览器

截图很有用，但不要截到 `.env` 或账户面板。

## 提交代码

- 一个 PR 只做一件事，改动越小越好合
- 提交信息写清「改了什么、为什么」，不要只写 `fix`
- 新增依赖前先在 issue 里说明理由，连同许可证一起
- 改动涉及下单、风控、账户权限时，PR 描述里必须写清影响范围

## 不要做的事

- 不要在 issue、讨论、PR、截图里贴 API key、私钥、助记词、钱包地址、账户余额截图
- 不要提交 `config/accounts*.json` 或任何 `.env`
- 不要发布收益截图、承诺收益、招揽资金或代客操作
- 不要贴别人的策略源码而不注明来源和许可

违反了会被直接删除并提醒；涉及资金安全的会移出组织。

## 关于策略与结论

贴策略时请一起给出：样本区间、样本外表现、最大回撤、失效条件。
只有样本内的漂亮曲线不构成结论。
